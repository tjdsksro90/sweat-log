# F. 체험 데모 — Claude

브랜치: `feat/demo`

## 목표

가입 없이 샘플 데이터로 땀일기를 써 보는 `/demo` 페이지를 만든다. 실제 앱 화면을 그대로 재사용하고, 데이터만 브라우저 안의 가짜 저장소로 바꾼다. 실제 DB와 로그인은 전혀 건드리지 않는다.

## 시작 시점

1단계 화면(기록 작성, 목록·상세·홈, 크루)이 모두 `main`에 병합된 뒤. 화면이 바뀌는 중에 시작하면 데모도 같이 고쳐야 한다.

## 참고

`j-yesung/did-what`의 `app/demo/`, `demo/` 구조를 참고한다. 그대로 베끼지 말고 땀일기 구조에 맞춘다.

- `/demo`: 소개 문구와 가운데 휴대폰 크기 iframe으로 앱(`/demo/app`)을 띄운다.
- 앱 안에서 이동은 `?path=` 쿼리로만 바꿔 서버를 다시 부르지 않는다(did-what `demo-href.ts`).
- 데이터는 `sessionStorage`에 둔다. 탭을 닫으면 사라지고 다른 탭과 섞이지 않는다(did-what `store.ts`).
- "처음부터 다시" 버튼으로 샘플 데이터로 되돌린다.

## 만들 것

1. 가짜 저장소와 샘플 데이터
   - 샘플 사용자 1명과 크루 1개(친구 3명), 최근 4주치 러닝·헬스·기타 기록, 댓글 몇 개
   - 날짜는 "오늘" 기준으로 만들어 언제 열어도 이번 주 요약과 연속 운동 일수가 채워져 있게 한다(한국 시간)
   - 저장소 함수는 실제 조회·저장 함수와 같은 모양(`contracts.ts`의 `WorkoutPage`, `WorkoutDetail`, `WeeklySummary`, `WorkoutInput`)을 돌려준다
2. 데이터 연결 바꾸기
   - 화면이 실제 조회 함수와 Server Action을 직접 부르면 데모에서 재사용할 수 없다. 화면(위젯·컴포넌트)이 데이터와 저장 함수를 props로 받는지 먼저 확인하고, 아니면 데이터 경계를 나누는 리팩터링을 따로 PR로 먼저 올린다.
   - 데모에서는 같은 위젯에 가짜 저장소의 데이터와 함수를 넘긴다.
3. 데모 화면
   - `/demo`(소개 + iframe), `/demo/app`(앱)
   - 홈, 기록 목록·달력·상세, 기록 작성·수정·삭제, 크루 피드, 댓글이 동작한다
   - 크루 만들기·초대 코드 가입은 "체험에서는 지원하지 않아요" 안내로 대신해도 된다
   - 로그인 확인(`proxy.ts`의 세션 갱신)을 타지 않도록 `src/shared/api/supabase/session.ts`의 `PUBLIC_PATHS`에 `/demo`를 추가한다(이 한 줄은 예외로 허용)
4. 로그인 화면에 "가입 없이 둘러보기" 링크
5. 가짜 저장소의 순수 로직(샘플 날짜 계산, 저장·삭제 후 목록·요약 갱신)은 Vitest로 테스트한다

## 수정 가능

`demo/` 또는 `src/demo/`(구조는 정해서 PR 설명에 적는다), `app/demo/`, `src/pages/auth/`(링크 한 줄), `src/shared/api/supabase/session.ts`(`PUBLIC_PATHS` 한 줄). 데이터 경계 리팩터링이 필요한 화면 폴더는 별도 PR로.

## 하지 않을 것

- 실제 DB, Supabase 호출, 로그인 세션 사용
- 화면 디자인 변경(필요하면 디자인 시스템 쪽에 요청)
- 데모 전용으로 화면을 복사해서 따로 만들기

## 완료 조건

- 시크릿 창에서 `/demo`를 열어 기록 작성 → 목록·상세·홈 요약에 반영 → 수정 → 삭제를 직접 해 본다
- 탭을 닫았다 열면 샘플 데이터로 돌아온다
- 네트워크 탭에 Supabase 요청이 없다
- 가짜 저장소 테스트, `pnpm lint`, `pnpm typecheck`, `pnpm test`
